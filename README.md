## Урок 1. Биты, байты, цифры и числа

### Цифра и число — разные понятия

Цифра — знак в записи числа. В десятичной записи используются цифры от 0 до 9. Число 507 записано тремя цифрами и означает `5 × 100 + 0 × 10 + 7 × 1`. Записи `007` и `7` могут обозначать одно число; как строки текста они различаются.

В двоичной записи используются две цифры: 0 и 1. Значения разрядов справа налево равны 1, 2, 4, 8 и далее. Поэтому двоичное `1011` обозначает `8 + 0 + 2 + 1 = 11`. Это другое представление того же числа, а не другое число.

**Бит** хранит одно из двух значений. **Байт** состоит из 8 битов. В восьми битах есть `2⁸ = 256` различных комбинаций. Если трактовать их как целые неотрицательные числа, получим диапазон от 0 до 255 включительно. Максимум равен 255, потому что ноль тоже занимает одну комбинацию.

| Количество битов | Комбинаций | Диапазон без знака |
| --- | --- | --- |
| 1 | 2 | 0…1 |
| 4 | 16 | 0…15 |
| 8 | 256 | 0…255 |

Сами биты не сообщают, что они означают. Программа должна знать правило интерпретации: число, часть текста или что-то другое. Размер данных ограничивает число представимых значений.

### Целые числа и знак

Целые числа не имеют дробной части: `-12`, `0`, `48`. Для отрицательных и положительных значений тоже нужны комбинации битов. В C# тип `int` хранит 32-битное целое со знаком: от `-2 147 483 648` до `2 147 483 647`. Отрицательных значений на одно больше, чем положительных; ноль занимает место в неотрицательной половине. Подробный алгоритм кодирования отрицательных чисел сейчас не требуется.

| Тип C# | Размер значения | Диапазон или назначение |
| --- | --- | --- |
| `byte` | 8 битов, 1 байт | 0…255 |
| `int` | 32 бита, 4 байта | −2 147 483 648…2 147 483 647 |
| `long` | 64 бита, 8 байтов | −9 223 372 036 854 775 808…9 223 372 036 854 775 807 |
| `double` | 64 бита, 8 байтов | Приближённые числа с дробной частью |
| `decimal` | 128 битов, 16 байтов | Десятичные вычисления с ограниченной точностью |

Размер значения в этой таблице не равен расходу памяти всей программы: у программы есть и другие данные и служебные расходы.

### Дробные числа и точность

Числа `1.5`, `-0.25`, `2.75` имеют дробную часть. Не всякую дробь можно точно записать конечным количеством разрядов: например, `1/3` в десятичной записи требует бесконечного повторения цифры 3. Аналогичная проблема есть у двоичной записи. `double` точно представляет некоторые дроби, например `0.5`, но десятичное `0.1` хранит приближённо.

`double` имеет примерно 15–17 значащих десятичных цифр точности. Это число цифр во всём значении, а не гарантированное число знаков после точки. Большой диапазон не означает, что все целые числа внутри него представимы точно: например, рядом с `2⁵³` расстояние между соседними представимыми значениями уже не всегда равно единице.

`decimal` удобен для сумм, заданных десятичными дробями: `0.1m` и `0.2m` представимы точно. Суффикс `m` означает литерал типа `decimal`. Но и этот тип конечен: `1m / 3m` остаётся приближением, а большие значения могут переполнить диапазон. Для упражнений с деньгами можно также хранить целое число копеек.

```csharp
Console.WriteLine(0.1 + 0.2 == 0.3);    // False
Console.WriteLine(0.1m + 0.2m == 0.3m); // True
```

Эти строки пока нужны как эксперимент. В следующих уроках мы разберём вызов вывода и сравнение. В исходном коде C# дробный литерал пишется с точкой; правила ввода пользователем отдельно обсудим в уроке 5.

### Ограничения хранения

Тип не превращает конечную память в бесконечную. Если вычисление выходит за диапазон `int`, возникает переполнение. В `checked`-контексте оно обнаруживается и приводит к исключению:

```csharp
int value = int.MaxValue;
Console.WriteLine(checked(value + 1)); // Выполнение завершится ошибкой переполнения
```

Без проверки некоторые целочисленные операции могут дать значение после перехода через границу диапазона. Не следует рассчитывать на такой результат как на обычную арифметику. Этот пример специально демонстрирует ошибку; обрабатывать исключения в первом уроке не требуется.

**Практика.** Переведи `1101` из двоичной записи в десятичную и 19 — обратно. Определи минимальное число битов для значений 0…100. Выбери тип для количества учеников, расстояния с дробной частью и количества копеек в небольшой покупке; объясни выбор. Придумай число, которое помещается в `long`, но не в `int`.

**Проверка понимания.** Почему 8 битов дают 256 комбинаций, но максимум `byte` равен 255? Чем число 12 отличается от текста `"12"`? Почему более широкий диапазон не гарантирует точные дроби? Можно ли хранить бесконечно много разных чисел в конечном числе битов?

## Урок 2. Как запускается программа: Main, вход и выход

Программа получает данные, выполняет действия и выдаёт результат. Не каждая программа обязана получать внешний ввод: данные могут быть записаны прямо в коде. Не каждый результат — возвращаемое значение: результат можно вывести на экран, записать или передать другой части программы.

Для занятий нужен .NET SDK и редактор. Создай отдельную рабочую папку, выполни `dotnet new console`, замени содержимое `Program.cs` следующим примером и запусти `dotnet run`. Команды создают учебный проект на твоём компьютере; этот репозиторий пока содержит только описание курса.

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("Программа запущена");
        Console.WriteLine($"Аргументов: {args.Length}");
    }
}
```

`Main` — метод, с которого начинается выполнение нашей программы. Параметр `args` — массив строк с аргументами командной строки. Здесь достаточно знать две операции: `args.Length` сообщает количество строк, а `args[0]` даёт первую строку, **если она существует**. Нумерация начинается с нуля. Перед обращением к первой строке нужно проверить длину.

`class Program` — минимальная оболочка, которую мы используем для размещения методов. `static` позволяет запускать этот метод без создания объекта. `void` говорит, что метод не возвращает значение. `using System;` позволяет писать `Console` вместо полного имени `System.Console`. Эти слова пока служат устройству файла, а не началу курса ООП. Фигурные скобки ограничивают блоки, точка с запятой завершает многие отдельные инструкции. Регистр букв важен.

Во всех следующих примерах, если не показана полная программа, код вставляется **внутрь тела Main** вместо прежних инструкций. Исключение — объявления методов в уроке 9: там отдельно указано их место. Используем одну и ту же оболочку и не смешиваем её с короткой записью программы без явного Main.

### Аргументы запуска и ввод с клавиатуры

Запуск `dotnet run -- apple 12` передаёт две строки: `"apple"` и `"12"`. Разделитель `--` отделяет параметры `dotnet run` от аргументов нашей программы. `Main` получает их при старте. Они не становятся числами автоматически.

`Console.ReadLine()` читает строку из стандартного ввода во время работы. В обычном интерактивном запуске это текст, который пользователь печатает и завершает Enter. Стандартный ввод может также поступать из файла или другой программы; конец ввода обозначается `null`.

`Console.Write` выводит текст без перехода на новую строку. `Console.WriteLine` выводит и завершает строку. Это **output**. Чтение данных — **input**. Приглашение «Введите число» само по себе ничего не читает.

`return` внутри `void Main` завершает метод без возвращаемого значения. Возможна другая форма — `static int Main(string[] args)`: возвращаемое целое тогда является кодом завершения для запускающей среды, обычно 0 означает успех. Это не обязательный способ передать ответ задачи пользователю. Ответ вычисления можно вывести в консоль, а обычный метод может вернуть значение вызывающему коду.

**Практика.** Запусти пример без аргументов, с одним и с двумя. Предскажи каждую строку вывода. Затем выведи два сообщения: сначала с `Write`, затем с `WriteLine`. Не добавляй чтение, пока не объяснишь отличие вывода от ввода.

**Проверка понимания.** Когда появляются аргументы? Почему строка `"12"` ещё не число? Что означает `void`? Чем вывод ответа отличается от кода завершения?

## Урок 3. Переменные, типы и присваивание

Переменная — именованное место для значения определённого типа. Тип задаёт допустимые значения и операции. Объявление `int count = 3;` создаёт переменную и задаёт начальное значение. Присваивание `count = 5;` заменяет прежнее значение.

```csharp
int count = 3;
int price = 40;
int total = count * price;
count = 5;
Console.WriteLine(total); // 120: total не пересчитывается сам
total = count * price;
Console.WriteLine(total); // 200
```

`=` — присваивание, а не математическое равенство. Правая часть сначала вычисляется, затем результат записывается в переменную слева. Поэтому `count = count + 1;` корректно: новое значение на единицу больше старого. В дальнейшем можно писать `count += 1;` или `count++;`.

Основные типы курса: `int` для целых, `double` для приближённых дробных вычислений, `decimal` для десятичных сумм, `string` для текста, `bool` для `true` или `false`. Литералы выглядят так: `42`, `2.5`, `2.5m`, `"Привет"`, `true`. У `string` нет универсального фиксированного размера, как у `int`: длина текста меняется.

```csharp
string item = "Тетрадь";
decimal price = 35.50m;
bool available = true;
Console.WriteLine($"{item}: {price}; в наличии: {available}");
```

Знак `$` перед строкой позволяет подставлять значения выражений из фигурных скобок. Имена вроде `count` и `price` сообщают смысл; имя `x` подходит для короткой математической задачи, но плохо объясняет цену покупки.

**Практика.** Запиши длину и ширину прямоугольника, вычисли площадь и периметр. Измени только ширину и пересчитай результаты. Составь таблицу значений переменных после каждой строки. Затем объясни, почему изменение ширины не изменило ранее вычисленную площадь автоматически.

**Проверка понимания.** Чем объявление отличается от последующего присваивания? Почему `int count = "3";` не подходит? Что произойдёт при присваивании одной переменной значения другой, если потом изменить вторую?

## Урок 4. Арифметика, деление и остаток

Операции `+`, `-`, `*`, `/` означают сложение, вычитание, умножение и деление. Скобки задают порядок. Умножение и деление выполняются раньше сложения и вычитания; операции одного приоритета обычно выполняются слева направо.

```csharp
Console.WriteLine(2 + 3 * 4);   // 14
Console.WriteLine((2 + 3) * 4); // 20
Console.WriteLine(7 / 2);       // 3
Console.WriteLine(7 % 2);       // 1
Console.WriteLine(7.0 / 2);     // 3.5
```

Когда оба операнда `/` целые, результат целочисленный: дробная часть отбрасывается в сторону нуля. Поэтому `-7 / 2` равно `-3`. `%` вычисляет остаток; для отрицательных операндов это не всегда тот положительный остаток, который ожидают из школьных задач. В первых упражнениях с остатком используем неотрицательные числа.

```csharp
double first = 7 / 2;         // 3: целое деление уже состоялось
double second = (double)7 / 2; // 3.5: один операнд преобразован до деления
Console.WriteLine(first);
Console.WriteLine(second);
```

Тип переменной назначения не меняет задним числом выполненную операцию. `(double)` — явное преобразование. Преобразование дробного значения в `int` отбрасывает дробную часть; это не округление до ближайшего целого. Используем его только когда значение помещается в целевой тип.

Делить целое число на ноль нельзя: выполнение приведёт к ошибке. Для вещественных типов правила отличаются; в наших программах проверяем допустимость знаменателя до вычисления.

**Практика.** Для 135 минут вычисли часы и оставшиеся минуты через `/` и `%`. Раздели 23 предмета между 5 участниками: сколько получит каждый и сколько останется? Рассчитай среднее двух целых чисел с дробной частью. Проверь случай 3 и 4: ответ должен быть 3.5.

**Проверка понимания.** Почему `double average = (3 + 4) / 2;` даёт 3? В каком месте нужно преобразование? Почему остаток и частное — разные результаты?

## Урок 5. Преобразование консольного ввода

Консоль получает текст. Даже если пользователь набрал цифры, программе нужно преобразовать строку в число. Ниже одновременно появляются чтение и минимальная проверка через `if`; подробно ветвления разберём в следующем уроке.

```csharp
Console.Write("Введите целое число: ");
string? text = Console.ReadLine();

if (!int.TryParse(text, out int number))
{
    Console.WriteLine("Не удалось прочитать целое число.");
    return;
}

Console.WriteLine($"Число: {number}");
```

`string?` сообщает, что вместо строки возможен `null`, то есть отсутствие значения. `TryParse` пытается выполнить преобразование и возвращает `bool`: успех или неуспех. `out int number` объявляет переменную, в которую метод записывает результат. При неуспехе она тоже получает значение, но использовать его как прочитанное число нельзя. `!` означает логическое отрицание. `return` прекращает Main, чтобы дальше не работать с неверным вводом.

`int.Parse` тоже преобразует строку, но при неподходящем тексте или выходе за диапазон выбрасывает исключение. Для пользовательского ввода в курсе выбираем `TryParse`: ошибка ввода — ожидаемый случай, который программа объясняет пользователю.

Дробный ввод зависит от культуры: в разных настройках десятичным разделителем бывает точка или запятая. Чтобы задания имели однозначное правило, можно явно потребовать точку:

```csharp
Console.Write("Введите дробное число с точкой: ");
string? text = Console.ReadLine();
bool ok = double.TryParse(
    text,
    System.Globalization.NumberStyles.Float,
    System.Globalization.CultureInfo.InvariantCulture,
    out double number);

if (!ok || !double.IsFinite(number))
{
    Console.WriteLine("Нужно конечное число с точкой.");
    return;
}

Console.WriteLine(number.ToString(System.Globalization.CultureInfo.InvariantCulture));
```

Длинные имена здесь задают формат, а не новую архитектуру. Проверка `IsFinite` исключает бесконечность и NaN — специальные значения `double`. Для первых задач достаточно целого ввода; дробный вариант нужен, когда задача действительно требует дробей.

**Практика.** Прочитай количество минут и выведи часы с остатком. Проверь `135`, `0`, `abc`, пустую строку и `2147483648`. Затем отдельно добавь запрет отрицательной длительности: правильный формат числа ещё не означает допустимые данные задачи.

**Проверка понимания.** Чем ошибка преобразования отличается от отрицательной длительности? Почему сообщение с приглашением не читает данные? Чем строка, пустая строка и конец ввода отличаются друг от друга?

## Урок 6. Условия и логические выражения

`if` выполняет блок, если условие равно `true`. `else` задаёт действие для другого случая. Сравнения `==`, `!=`, `<`, `>`, `<=`, `>=` дают логическое значение. Не путай `==` с присваиванием `=`.

```csharp
int temperature = 0;
if (temperature < 0)
{
    Console.WriteLine("Ниже нуля");
}
else if (temperature == 0)
{
    Console.WriteLine("Ровно ноль");
}
else
{
    Console.WriteLine("Выше нуля");
}
```

`&&` означает «и», `||` — «или», `!` — «не». Для допустимого диапазона от 1 до 10 включительно: `number >= 1 && number <= 10`. Эти операции выполняют короткую проверку: `&&` не вычисляет правую часть, если левая уже ложна; `||` не вычисляет её, если левая уже истинна.

Теперь можно безопасно прочитать первый аргумент запуска:

```csharp
if (args.Length == 0)
{
    Console.WriteLine("Передайте имя при запуске.");
    return;
}
Console.WriteLine($"Привет, {args[0]}!");
```

**Практика.** Прочитай целое число и сообщи, положительное оно, отрицательное или ноль. Затем проверь, находится ли оно в диапазоне 1…10. Для задачи о билетах самостоятельно задай понятное правило скидки по количеству, запиши его словами и реализуй. Не вводи реальные тарифы: это учебная модель.

**Проверка понимания.** Чем цепочка `if / else if / else` отличается от трёх отдельных `if`? Что случится ровно на границе диапазона? Почему перед `args[0]` проверяется длина?

## Урок 7. Цикл while и повторный ввод

`while` проверяет условие перед каждым повторением. Если оно изначально ложно, тело не выполнится ни разу. Нужно понимать, что изменится после шага и почему цикл когда-нибудь остановится.

```csharp
int remaining = 3;
while (remaining > 0)
{
    Console.WriteLine(remaining);
    remaining--;
}
Console.WriteLine("Готово");
```

Удаление `remaining--` делает этот цикл бесконечным. Проверяй ход выполнения таблицей: значение перед проверкой, результат условия, вывод, новое значение.

Для ввода до получения допустимого числа можно использовать явно бесконечный цикл с выходами:

```csharp
while (true)
{
    Console.Write("Введите число от 1 до 10: ");
    string? text = Console.ReadLine();
    if (text == null)
    {
        return; // Конец ввода: ждать новые строки уже неоткуда
    }
    if (int.TryParse(text, out int number) && number >= 1 && number <= 10)
    {
        Console.WriteLine($"Принято: {number}");
        break;
    }
    Console.WriteLine("Попробуйте ещё раз.");
}
```

`break` завершает ближайший цикл; после него выполнение продолжается за циклом. `return` завершает весь текущий метод. У этого примера два осмысленных выхода: корректные данные и конец ввода.

**Практика.** Сделай обратный отсчёт от заданного неотрицательного числа. Затем организуй ввод положительной длительности с повторными попытками. Проверь последовательность `abc`, `-5`, `0`, `12`, а также конец ввода.

**Проверка понимания.** Может ли while не выполниться ни разу? Что обеспечивает завершение? В чём различие между `break` и `return`?

## Урок 8. Цикл for, счётчик и накопление

`for` удобен, когда известен порядок изменения счётчика. В заголовке стоят начальное действие, условие продолжения и действие после каждого шага.

```csharp
int sum = 0;
for (int i = 1; i <= 5; i++)
{
    sum += i;
}
Console.WriteLine(sum); // 15
```

`sum` — накопитель. Он объявлен перед циклом, чтобы сохранять результат между шагами и быть доступным после цикла. Если обнулять сумму внутри тела, предыдущие слагаемые потеряются. Условие `i <= 5` включает последний шаг, а `i < 5` исключает его.

При вводе границ учитывай диапазон результата и счётчика. Для учебных задач задавай небольшие ограничения, например `n` от 1 до 1000. Это позволяет объяснить, почему сумма помещается в выбранный тип, вместо надежды, что переполнения не будет.

**Практика.** Выведи таблицу умножения выбранного числа от 1 до 10. Вычисли сумму от 1 до `n`, где `1 <= n <= 1000`. Посчитай, сколько чисел от 1 до `n` делятся на 3 без остатка. Сначала реши для `n = 1`, `3`, `4` и сравни с ручным счётом.

**Проверка понимания.** Сколько шагов выполняет цикл от 0 при условии `i < 5`? Почему сумма начинается с нуля? Где должна находиться переменная, которая хранит число найденных значений?

## Урок 9. Простые методы: параметры и return

Метод выделяет действие с ясным назначением. Параметры получают значения при вызове; возвращаемое значение передаёт результат вызывающему коду. Это помогает проверить вычисление отдельно от чтения и вывода.

Полная программа показывает, где объявляется метод: **внутри Program, рядом с Main, а не внутри тела Main**.

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        int result = RectangleArea(4, 7);
        Console.WriteLine(result);
    }

    static int RectangleArea(int width, int height)
    {
        return width * height;
    }
}
```

Вызов передаёт 4 в `width`, 7 в `height`. `return` возвращает 28, и Main записывает его в `result`. Метод ничего не печатает. Для этой учебной функции договоримся: стороны неотрицательны и не больше 1000. При таких входах результат помещается в `int`. Проверка входа может находиться перед вызовом.

Параметры метода и аргументы командной строки — связанные, но разные понятия. Параметр — имя в объявлении метода; аргумент вызова — переданное значение. Аргументы командной строки — строки, пришедшие при запуске и переданные в параметр `args` метода Main.

**Практика.** Напиши `static bool IsEven(int number)`, возвращающий результат проверки чётности. Затем напиши метод для среднего двух целых чисел от −1000 до 1000 с результатом `double`. Вызови каждый метод несколько раз и сравни результаты с ручным расчётом. Не размещай чтение консоли внутри этих вычислительных методов.

**Проверка понимания.** Чем возвращение значения отличается от его печати? Может ли вызывающий код использовать результат метода в другом выражении? Почему полезно договориться о допустимых входных данных?

## Урок 10. Проверка, ошибки и отладка

Есть как минимум три разных ситуации: код не компилируется; программа запускается, но останавливается с ошибкой; программа завершается, но ответ неверен. В последнем случае отсутствие сообщения об ошибке не доказывает правильность.

Сначала прочитай сообщение компилятора и найди строку. Затем проверь типы, скобки, имена и доступность переменных. Для неверного результата запиши ожидаемый ответ независимо от программы, проследи изменения значений и при необходимости временно выведи промежуточные результаты. Меняй одну причину за раз.

| Проверка для ввода минут | Что должно произойти |
| --- | --- |
| `135` | 2 часа и 15 минут |
| `60` | 1 час и 0 минут |
| `0` | 0 часов и 0 минут, если ноль разрешён |
| `59` и `61` | Правильная работа по обе стороны границы часа |
| `-1` | Сообщение о недопустимой длительности |
| `abc`, пустая строка | Сообщение о неверном формате |
| Число за диапазоном `int` | Отказ при преобразовании |
| Конец ввода | Завершение без бесконечных повторений |

**Практика.** Найди три ошибки в собственной ранней версии: например, целое деление вместо дробного, пропущенную границу цикла и накопитель, обнуляемый на каждом шаге. Для каждой запиши вход, на котором ошибка видна, причину и результат после исправления. Не считай задачу проверенной одним удачным запуском.

**Проверка понимания.** Чем ошибка алгоритма отличается от синтаксической ошибки? Почему 60 — полезнее случайного большого числа при проверке перевода минут? Как отличить неверное ожидание от неверной программы?

## Урок 11. Законченные маленькие консольные программы

Выбери два задания. Сначала напиши план обычными словами, затем код. Готовое решение должно иметь понятные приглашения, проверку входа, результат с единицами измерения и предсказуемое завершение.

### A. Перевод времени

Вход: целое количество минут от 0 до 1 000 000. Выход: часы и оставшиеся минуты. Программа повторяет ввод при ошибке и завершается при конце ввода. Дополнительное требование: принимать количество минут первым аргументом командной строки, если он передан; иначе читать консоль. Неверный аргумент должен вызывать понятное сообщение, а не молча заменяться другим числом.

Вопросы до кода: где используются `/` и `%`? Какие значения являются границами? Что будет при нескольких аргументах? Выбери и опиши правило: например, разрешён ровно один аргумент.

### B. Стоимость покупки

Вход: количество от 1 до 100 и целая цена в копейках от 0 до 100 000. Выход: общая стоимость в рублях и копейках. Сформулируй учебное правило скидки, например 10% при количестве от 10, и отдельно реши, как округлять неполную копейку. Для первого варианта можно обойтись без скидки, затем добавить её как изменение требований.

Вопросы до кода: помещается ли максимальная стоимость в `int`? Где нужна проверка диапазона? Как вывести оставшиеся копейки двумя цифрами? Для последнего шага можно использовать формат `{kopecks:D2}` внутри интерполированной строки; `D2` дополняет целое значение нулём слева до двух цифр.

### C. Статистика небольшого набора

Вход: количество значений от 1 до 100, затем столько же целых чисел от −1000 до 1000. Выход: сумма, минимум, максимум и среднее с дробной частью. Массив не обязателен: обработай каждое число сразу, используя накопители. Минимум и максимум удобно начать с первого успешно прочитанного значения.

Вопросы до кода: почему нельзя всегда начинать минимум с нуля? Что получится для единственного числа? Как не потерять дробную часть среднего? Что делать с неверной строкой — повторять ввод того же значения или засчитывать шаг? Обоснуй выбранный вариант.

### D. Угадай заданное число

Программа хранит секретное целое число от 1 до 100, читает попытки и сообщает «меньше», «больше» или «угадано». Считает только корректные попытки. Случайный генератор пока не нужен: секрет можно задать в переменной и менять перед запуском.

Вопросы до кода: в какую сторону должна указывать подсказка? Когда увеличивается счётчик? Что завершает цикл? Проверь число на границе и несколько неверных строк подряд.

После первого рабочего варианта подготовь минимум шесть проверок: обычный случай, две границы, неверный формат, недопустимое число и завершение ввода. Если есть дробные вычисления, добавь случай с нецелым ответом. Ожидаемые результаты должны быть записаны до запуска.

Объясни программу без чтения комментариев: какие значения хранят переменные, в какой последовательности выполняются действия, как выбираются ветки, почему заканчиваются циклы, что возвращают методы.
